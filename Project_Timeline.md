# 🔄 GitHub Workflow

## Branching Strategy

Each user story should be developed on its own branch.

Examples:

```text
main
├── feature/US-01-add-movies
├── feature/US-02-categorize-movies
├── feature/US-03-rate-movies
├── feature/US-04-watched-status
├── feature/US-05-delete-movies
├── feature/US-06-display-library
├── feature/US-07-search-movies
├── feature/US-08-sort-movies
├── feature/US-09-edit-movies
├── feature/US-10-random-recommendation
├── feature/US-11-genre-suggestions
└── feature/US-12-unwatched-movies
```

## Development Process

1. Create or assign a GitHub Issue.
2. Create a feature branch.
3. Implement and test the feature.
4. Commit changes with a descriptive message.
5. Push the branch to GitHub.
6. Open a Pull Request.
7. Request a review from another team member.
8. Merge after successful review.
9. Close the related Issue.

### Example Commit Messages

```text
feat: implement movie deletion
feat: add movie sorting by rating
fix: handle invalid movie selection
test: add tests for movie editing
docs: update README instructions
```
